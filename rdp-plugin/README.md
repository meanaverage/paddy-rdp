# Bundled Remote Desktop

This is the Tauri adaptation of [tabby-rdp](https://github.com/meanaverage/tabby-rdp), based on version **0.6.0**, source commit `9e9d56a` (tag `v0.6.0`; before it, 0.5.6 at `f27955e`). The original MIT license and IronRDP vendor licenses are included. The vendor JavaScript and WASM are unchanged from that release: IronRDP with its patches through 59, among them Windows Server hosts with RDS licensing answered as mstsc does (#106) and the bitmap cache and Progressive tiles kept across a resize (#115).

The connection, shared-drive, process, and clipboard bridges started from the Tauri implementation in `meanaverage/tabbz` at `fa3ae85`. They have been adapted to this host and the current plugin's APIs. Native transport lives in `src-tauri/src/rdp/`; the page runs IronRDP and the plugin interface. No Node or Electron installation is required at runtime.

Create a **Remote desktop (RDP)** profile in Settings → Profiles & connections. It can connect directly, through an SSH profile, or through an RD Gateway. Settings → Remote Desktop contains the plugin's preferences, accounts, shared folders, and help. An SSH terminal also gains the desktop controls.

## Host-specific changes

- Built and loaded as a built-in plugin, with its scripts and WASM served from the app's own assets.
- Target identities, nested-host keys, sign-in names and credential/trust scopes use the synchronous [Rust identity page core](../src-tauri/rdp-identity-core/README.md). The page retains profiles, keychain access and UI.
- Desktop configuration, duplicate restrictions, xrdp consent, wake parsing and clipboard decisions use the [Rust desktop policy core](../src-tauri/rdp-desktop-core/README.md). The page retains vendor hook composition, original paste targets and platform effects.
- Clipboard file-request admission, queues, reservations, expiry and response identities use the [Rust transfer core](../src-tauri/rdp-transfer-core/README.md). The page retains file objects, disk promises, permissions, vendor callbacks and connection flow effects.
- Audio resampling, PCM conversion, playback timing and counters use the [Rust audio core](../src-tauri/rdp-audio-core/README.md) through binary buffers. Web Audio owns devices, capture nodes and playback; microphone permission is still requested only by the existing capture path.
- System SSH discovery, companion-option filtering, `ssh -G` capture and nested report parsing use the [SSH target core](../src-tauri/ssh-target-core/README.md). The page retains its terminal identity, probe observations, profile/key mapping and UI.
- RDP setup/probe commands collect stdout, enforce deadlines and clean up owned children/channels natively through the [remote command core](../src-tauri/rdp-command-core/README.md). The page retains transport discovery, argv construction and failure presentation.
- `.rdp` import parsing runs in the native blocking pool through the portable [RDP file core](../src-tauri/rdp-file-core/README.md). The page keeps file selection, destination confirmation and profile creation; the diagnostic `parseRdpFile` hook now returns a promise.
- Native loopback WebSocket/TLS proxy, authenticated both at the HTTP upgrade and in the RDCleanPath request. Direct and gateway certificate trust uses the system certificate store; unverified certificates require confirmation. Non-NLA approval remains bound to the accepted certificate.
- SSH desktop channels stay native, independently of terminal output. Closing/reloading a page releases owned proxies, files, temporary downloads, and subprocesses.
- Current release's sign-in/account revisions, clipboard direction controls, bounded streaming download/upload logic, and separate WASM instances are retained. Shared drives use the native confined filesystem implementation.
- Browser clipboard methods use the native clipboard bridge. Test copies use a private clipboard and test password store.
- Plugin updates are delivered with app builds. The npm installer is not offered here because that package requires Electron.
- Certificate prompts retain the fingerprint and native validation verdict; the Node-specific detailed X.509 subject/issuer display is not supplied by the native bridge.
- The header auto-hide of tabby-rdp 0.6.0 is Paddy's own here, with the sidebar's beside it (itabby-plugin's `autoHide.ts`: Settings → Paddy, View → Hide Header and Hide Sidebar, with the window buttons hidden natively). This plugin supplies only their Automatic condition, `RemoteDesktopService.singleDesktopVisible()`, as 0.6.0 has it, and keeps a resize reconnect at the size it asked for while the header comes back during the reconnect (`initialSize`). Left out: `headerVisibility.ts`, the Auto-hide header and Minimum window size rows, their `headerAutoHide`/`headerMinWidth`/`headerMinHeight` settings, `header.ts`' wait for a hidden header, and the `@electron/remote` View menu item.
- 0.6.0's Go network helper (`proxyHelper.ts`) and the rewrite of `rdcleanpath.ts` around it are not taken: the native transport above does what the helper does there, TLS included. It uses rustls, which offers only ECDHE key exchange and doesn't enforce key usage, so Windows' default self-signed certificate (#102) connects as it is. The helper-only additions to `authorities.ts` (`peerCertificate`, `validity`, `authoritiesPem`, which need Node's `tls` and `X509Certificate`) are left out too.
- Left for later: the FreeRDP client (`freerdp.ts`, `freerdpView.ts`, `rdpClient.ts`, the client choice in Settings, profiles, desktops and the RDP client tab menu, the FreeRDP compatibility settings for glyph caching and relaxed drawing-order checks, their profile and desktop fields, and its helper packages), and the PDU traces (`pduTrace.ts`, `zgfx.ts`, `tools/pdu-trace`). Nothing of either is in this copy: no imports, settings rows, config defaults or profile fields.
- The diagnostic log file (Settings → Remote Desktop → Settings → Diagnostics) is written through the native file bridge, a write for each batch of lines rather than each line, in `~/.tabby-rdp-logs` (Paddy's platform service names no config path), its mode set after making it (the bridge makes folders without one); the log folder link opens it with macOS's `open`, and the log's first line names Paddy's version in place of Electron's and Node's.
- 0.6.0's macOS file paste fix for Electron without native path resolution (`fileTransfer.ts`' `realpath`) is taken as it is; the fs bridge has `realpathSync.native`, so it changes nothing here, and copied files' paths still come from the native clipboard bridge.

## Updating

Update this source from a specific tabby-rdp release, preserve these host adaptations, and update this provenance note. A three-way merge (`git merge-file`: this copy, the release it is based on, the new one) shows what Paddy changed; settings and markup strings are written in parts joined with `+` as upstream writes them, which `scripts/settings-guide.mjs` reads. Do not replace the directory with the npm bundle. Run `node scripts/check-rdp-assets.mjs` to verify the vendor files against `vendor/SHA256SUMS`, build both hosts, run the native tests and shared `scripts/rdp-checks.mjs` checks, and test an actual desktop before a release intended for broad distribution.

Paddy and tabbi build independently. Neither consumes the other's working tree. Shared RDP changes must be brought into both repositories explicitly.
